## Q1. Canonical benchmark datasets per task family (size, balance, homology filter, SOTA, download)

### Takeaway
Protein–DNA/RNA binding-site prediction has the best-documented public benchmarks (TR646/TE46 from DBPred; GraphBind DNA-573/DNA-129, RNA-495/RNA-117, plus newer DNA-181/RNA-285), all CD-HIT 30%-filtered with ~4–12% positive residues and published MCC/AUC tables. The advisors' own task families (ATP/FAD/NAD/Ca, efflux, IL-6/IL-13/IFN-γ epitopes, neoantigens) mostly ship their data inside the group's GitHub repos rather than Zenodo, and several report only AUC/MCC without a shared leaderboard — so "SOTA" there is effectively the group's own last paper.

### Cited Findings

**Protein–DNA binding residues (TR646/TE46, TR573/TE129)**
- Dataset1 (from DBPred): TR646 = 646 proteins, 15,636 DNA-binding and 298,503 non-binding residues (4.98% positives); TE46 = 46 proteins, 965 binding / 9,911 non-binding (8.87% positives) — Table 1 of the CLAPE paper, [CLAPE preprint PDF](https://arxiv.org/pdf/2306.15912). (Note: a secondary summary states 956 binding residues for TE46; the paper's Table 1 says 965 — [search summary conflict noted](https://academic.oup.com/bib/article/25/1/bbad488/7505238).)
- Dataset2 (from GraphBind): TR573 = 573 proteins, 14,479 binding / 145,404 non-binding (9.06%); TE129 = 129 proteins, 2,240 binding / 35,275 non-binding (5.97%) — [CLAPE preprint PDF](https://arxiv.org/pdf/2306.15912).
- Redundancy control for both: "reducing the sequence similarity using a cutoff of 30% with CD-HIT"; binding residue defined by distance < 0.5 Å + sum of van der Waals radii of the two nearest atoms — [CLAPE preprint PDF](https://arxiv.org/pdf/2306.15912).
- CLAPE-DB SOTA on TE46 (ProtBert frozen + 1D-CNN + focal loss + contrastive loss): Spe 0.835, Rec 0.747, Pre 0.306, F1 0.434, MCC 0.401, AUC 0.871; beats DBPred by 25.3% on MCC. On TE129: table reports DRNAPred MCC 0.155 / AUC 0.693, DNAPred 0.332 / 0.845, SVMnuc 0.304 / 0.812, and CLAPE-DB AUC 0.881 — [CLAPE preprint PDF](https://arxiv.org/pdf/2306.15912).
- Swapping ProtBert for ESM-2 inside CLAPE-DB (no other change): TE46 AUC 0.871→0.888, AUPR 0.463→0.517; TE129 AUC 0.881→0.908, AUPR 0.411→0.528 — Supplementary Table 9, [CLAPE preprint PDF](https://arxiv.org/pdf/2306.15912).
- Structure-based GraphBind on TE129 *with predicted structures* dropped to AUC 0.816, below sequence-only CLAPE-DB — [CLAPE preprint PDF](https://arxiv.org/pdf/2306.15912).
- Code/data: https://github.com/YAndrewL/clape — [CLAPE preprint PDF](https://arxiv.org/pdf/2306.15912).

**GraphBind family, incl. the newer larger test sets**
- DNA-573_Train 573 proteins / 14,479 pos / 145,404 neg (ratio 0.100); DNA-129_Test 129 / 2,240 / 35,275 (0.064); DNA-181_Test 181 / 3,208 / 72,050 (0.044); RNA-495_Train 495 / 14,609 / 122,290 (0.119); RNA-117_Test 117 / 2,031 / 35,314 (0.058); RNA-285_Test 285 / 4,245 / 41,399 (0.102) — Table 1 of MegSite, [MegSite (PMC12496013)](https://pmc.ncbi.nlm.nih.gov/articles/PMC12496013/).
- Filtering in that benchmark line: "CD-HIT program was utilized with a clustering threshold of 0.3", plus US-align removal of proteins with TM-score > 0.5 — [MegSite](https://pmc.ncbi.nlm.nih.gov/articles/PMC12496013/).
- Current numbers (MCC / AUC): DNA-129 — MegSite 0.567/0.952, EquiPNAS 0.552/0.943, GeSite 0.522/0.941. DNA-181 — MegSite 0.444/0.932, EquiPNAS 0.410/0.921. RNA-117 — MegSite 0.411/0.899, EquiPNAS 0.371/0.887. RNA-285 — MegSite 0.421/0.873, GeSite 0.395/0.851 — [MegSite](https://pmc.ncbi.nlm.nih.gov/articles/PMC12496013/).
- MegSite data + weights + code: https://github.com/pengsl-lab/MegSite — [MegSite](https://pmc.ncbi.nlm.nih.gov/articles/PMC12496013/). Original GraphBind dataset page: http://www.csbio.sjtu.edu.cn/bioinf/GraphBind/datasets.html — [GraphBind datasets page](http://www.csbio.sjtu.edu.cn/bioinf/GraphBind/datasets.html).
- A "TR735/TE180" DNA variant is used by the advisors' RAG_DNA_RNA repo; I counted from the repo's own label files: TR735 = 735 sequences, 18,611 positive and 178,125 negative residues (9.5% positives); TE180 = 180 sequences, 4,255 pos / 60,964 neg (6.5%) — computed from [TR735_labels.txt](https://github.com/mhb1717/RAG_DNA_RNA/blob/main/TR735_labels.txt) and [TE180_labels.txt](https://github.com/mhb1717/RAG_DNA_RNA/blob/main/TE180_labels.txt).

**ATP binding residues**
- ATP-227 = 227 non-redundant chains with pairwise identity strictly < 40%; ATP-388 / ATP-41 are the standard train/independent-test pair, with ATP-17 the second test set — [Weighted ensemble Transformer+DQN, IJMS 2026 (PMC13073818)](https://pmc.ncbi.nlm.nih.gov/articles/PMC13073818/).
- Recent results: fractional-order CNN + PLM reports ATP-17 AUC 0.965, accuracy 0.990, specificity 0.997; ATP-41 (trained on ATP-388) AUC 0.941, accuracy 0.984 — [Scientific Reports 2025](https://www.nature.com/articles/s41598-025-25830-7). Transformer+DQN ensemble reports ATP-41 AUC 0.9188 / MCC 0.6564 and ATP-17 AUC 0.9353 / MCC 0.6625 — [PMC13073818](https://pmc.ncbi.nlm.nih.gov/articles/PMC13073818/).
- Advisor-group ATP work: ATP_mCNN (PLM + multi-window CNN) reports AUC 0.95 on benchmark data — Comput Biol Med 2025;185:109541, [PubMed 39653625](https://pubmed.ncbi.nlm.nih.gov/39653625/).
- RTK_RAG (ATP sites in receptor tyrosine kinases, RAG + MCNN): train set ATP-549 = 549 proteins, 8,502 ATP-binding and 205,035 non-binding residues (4.0% positives); independent RTK test = 69 proteins, 711 binding / 73,270 non-binding (0.96% positives — extremely imbalanced); RAG database = 244 proteins, 2,676 binding / 261,088 non-binding — [RTK_RAG README](https://github.com/B1607/RTK_RAG).
- RTK_RAG reported metrics: AUC 0.9868, sensitivity 0.9747, accuracy 0.9895, MCC 0.6782; CD-HIT was run once at a 40% identity threshold on both data sets (including an RTK(313) set) — extracted from the published PDF in the repo (`docs/common/advisor/Prof Ou/ci5c00766.pdf`), J Chem Inf Model 2025;65(13):7277–7284, [PubMed 40531492](https://pubmed.ncbi.nlm.nih.gov/40531492/).

**FAD binding sites**
- msCNN-PLM-FAD: dataset of 12,850 samples after using BLAST to remove sequences with identity > 30%; AUC 0.9614, MCC 0.7491, specificity 0.9836, accuracy 0.9795, sensitivity 0.8704, with ESM-2 650M embeddings (MCC 0.7491 vs 0.5417 for the next-best embedding) — Anal Biochem 2026;713:116092, [PubMed 41763284](https://pubmed.ncbi.nlm.nih.gov/41763284/), numbers verified in the local PDF `docs/common/advisor/Prof Ho/1-s2.0-S0003269726000485-main.pdf`.
- Same paper's ablations (useful as baselines to reproduce): window size 12 → MCC 0.6676/best single window; 1024 hidden nodes → MCC 0.7321; filter size 512 → MCC 0.7491; 5-fold CV MCC peaked at window length 17 with 0.6559 ± 0.0754; mean AUC 0.9661 ± 0.0108 — local PDF as above.
- Public code/data: https://github.com/kioenguyen0207/msCNN-PLM-FAD — repo holds `data/fasta/fasta.sites.train.txt` (20 sequences) and `fasta.sites.test.txt` (4 sequences), per-sequence label JSONs, and one `sample_data.csv` (7 rows × 16,641 columns, i.e. 13×1280 ESM features flattened) — my inspection of the repo tree via the GitHub API.

**NAD+ / sirtuin deacetylase binding sites**
- NAD_MCNN: AUC 0.9733 for human sirtuin proteins and 0.9701 for other NAD-dependent deacylation enzymes — Chem Biol Drug Des 2025;105(4):e70085, [PubMed 40183480](https://pubmed.ncbi.nlm.nih.gov/40183480/).

**Calcium binding sites in channels/transporters**
- CaBind_MCNN: ProtTrans embeddings + multi-window CNN, trained on a curated set of just **27 calcium-binding protein sequences**, AUC 0.9886 — J Chem Inf Model 2025;65(4):2145–2157, [PubMed 39916334](https://pubmed.ncbi.nlm.nih.gov/39916334/).

**Metal-ion binding sites (broader, non-group benchmark)**
- LMetalSite built four BioLiP-derived benchmarks for Zn²⁺, Ca²⁺, Mg²⁺, Mn²⁺; average AUC 0.913 (5-fold CV) and 0.928 (independent), average AUPR 0.540 / 0.559; per-ion independent AUPR 0.803, 0.492, 0.316, 0.625; AUPR chosen over AUC because it is "more sensitive and informative than AUC in imbalanced classification tasks" — [Briefings in Bioinformatics 2022, bbac444](https://academic.oup.com/bib/article/23/6/bbac444/6770088).

**Efflux protein families**
- DeepEfflux original data: MFS 755 sequences, SMR 15, MATE 41, RND 202, ABC 1,670; classes grouped as A = MFS+SMR+MATE, B = RND, C = ABC — [DeepEfflux, Bioinformatics 2018](https://academic.oup.com/bioinformatics/article/34/18/3111/4970514). (The thesis brief cites ABC 2394 vs SMR 18; those differ from the DeepEfflux paper's counts, so the brief's numbers likely come from the newer GenEfflux curation — I could not find a public table confirming them.)
- mCNN-GenEfflux (ProtGPT2-generated sequences + multi-window CNN + PSSM) vs DeepEfflux baseline: Class B sensitivity 0.5385 → 0.9999, MCC 0.4397 → 0.9327; Class C accuracy 0.8977 → 0.9668, MCC 0.7668 → 0.9331 — Comput Biol Chem 2025;119:108595, [PubMed 40690811](https://pubmed.ncbi.nlm.nih.gov/40690811/). This is the direct precedent for the "generative augmentation for rare families" thesis direction.
- Earlier group work on efflux identification with BERT+SVM reports 94.15% and 87.13% accuracy on membrane and transport independent tests — Anal Biochem 2021;633:114416, [PubMed 34656612](https://pubmed.ncbi.nlm.nih.gov/34656612/).

**Transporters / glucose transporters**
- TCDB: 20,653 proteins in 15,528 non-redundant transport systems, 1,536 transporter families, the only transport classification DB adopted by IUBMB — [TCDB 2021 update, NAR](https://academic.oup.com/nar/article/49/D1/D461/5973435); downloads at https://www.tcdb.org.
- GT-Finder discriminates three glucose transporter families (GLUTs, SGLTs, SWEETs) with pre-trained BERT; BERT-Base/Large improved average sensitivity and MCC by more than 4% — Comput Biol Med 2021, [ScienceDirect S0010482521000536](https://www.sciencedirect.com/science/article/abs/pii/S0010482521000536) (also in repo as `docs/common/advisor/Prof Ho/1-s2.0-S0010482521000536-main.pdf`).
- mCNN-glucose (multiple-scanning-window CNN for glucose transporter families) is the follow-up, Int J Biol Macromol 2025 — [ScienceDirect S0141813025000716](https://www.sciencedirect.com/science/article/abs/pii/S0141813025000716).
- Mitochondrial carriers: MCNN_MC, J Chem Inf Model 2024;64(24):9125–9134 — [PubMed 39133248](https://pubmed.ncbi.nlm.nih.gov/39133248/).

**Cytokine-inducing epitopes**
- IL-13: DeepEpiIL13 benchmark = 2,576 training peptides (250 positive / 2,326 negative, 9.7% positives), 645 test (63 / 582), plus an independent SARS-CoV-2 set of 52 (12 / 40). Reported MCC 0.52 / AUC 0.86 on the benchmark and MCC 0.63 / AUC 0.92 on SARS-CoV-2; prior Pfeature-based works got MCC 0.3 / AUC 0.8 (2022) and MCC 0.33 / AUC 0.83 (2023) — [DeepEpiIL13 README](https://github.com/s1101404/DeepEpiIL13) and ACS Omega 2025;10(9):9675–9683 ([PubMed 40092768](https://pubmed.ncbi.nlm.nih.gov/40092768/)), numbers cross-checked in local PDF `docs/common/advisor/Prof Ou/ao4c10960.pdf`.
- IL-6: the standard IL6Pred benchmark is 365 IL-6-inducing and 2,991 non-inducing peptides (10.9% positives); IL6Pred's own best RF validation AUC 0.83 / MCC 0.31 — [IL6Pred-derived summary, Sci Rep 2025](https://www.nature.com/articles/s41598-025-05491-2); dataset mirror on Zenodo: https://zenodo.org/records/20033778.
- Group's IL-6 model: RAG_MCNNIL6 (ProtTrans + RAG retrieval + multi-window CNN), J Chem Inf Model 2025;65(5):2685–2694 — [PubMed 39967508](https://pubmed.ncbi.nlm.nih.gov/39967508/). The abstract claims superiority but gives no numeric MCC/AUC in the abstract text.
- IFN-γ: IFNepitope2 human validation AUC 0.90 / MCC 0.66; mouse 0.85 / 0.55 — [IFNepitope2-derived comparison](https://pmc.ncbi.nlm.nih.gov/articles/PMC12801304/); dataset mirror: https://zenodo.org/records/19913063. Group's IFNg_DeepKG (ESM-2 + knowledge-graph RAG + multiscale CNN) reports AUC 0.99 on human H_IFNgInd1 and 0.95 on mouse M_IFNgInd1, 0.94 cross-species — J Chem Inf Model 2026;66(1):770–784, [PubMed 41474270](https://pubmed.ncbi.nlm.nih.gov/41474270/).

**Neoantigens**
- DeepNeoAG pipeline: 32,877 epitope sequences → 7,019 after removing similarity < 30% → 7,012 after length < 35 filter → 5,608 train / 1,404 test. Positives: 671 → 303 → 302 neoantigens (241 train / 61 test); negatives 32,206 → 6,717 → 6,710 (5,367 / 1,343). Positive rate ≈ 4.3%. Test split by MHC class: MHC I 1,023 (18 pos), MHC II 281 (43 pos) — [DeepNeoAG README](https://github.com/B1607/DeepNeoAG); paper Int J Biol Macromol 2024;281:136252, [PubMed 39366619](https://pubmed.ncbi.nlm.nih.gov/39366619/).
- Successor NeoGen-BC (PLM + RAG + MCNN-BiLSTM + ProtGPT2 generation, breast cancer) reports AUC 0.9053 on an independent test set — Biochem Biophys Res Commun 2026;836:154567, [PubMed 42721858](https://pubmed.ncbi.nlm.nih.gov/42721858/).

### Inferences
- The leakage-audit thesis direction has the cleanest target in the group's own RAG papers: RTK_RAG's RAG database (244 proteins) and its ATP-549 training set are both published as FASTA in the repo, so an overlap/identity audit (CD-HIT or MMseqs2 between RAG DB, train, and the 69-protein RTK test) is a few CPU-hours of work with no GPU at all. Same for RAG_DNA_RNA (TR735/TE180 plus a RAG-DB builder script).
- Two datasets stand out as genuinely dangerous to draw conclusions from: CaBind_MCNN (27 sequences) and the RTK test set (0.96% positive residues). Both are places where an audit-style thesis has real headroom — a 0.9886 AUC on 27 sequences is almost certainly not an estimate of generalization.
- For the rare-class/imbalance direction, DeepEfflux's SMR class (15–18 sequences) and DeepNeoAG's 302 positives are the natural testbeds, and mCNN-GenEfflux already set the precedent (and the number to beat) for generative augmentation; a thesis would need a *fair* comparison protocol because a Class-B sensitivity of 0.9999 on a 202-sequence family is itself suspicious.
- Positive-residue rates cluster at 4–10% for binding-site tasks, so AUPR/MCC rather than accuracy/AUC must be the headline metric (LMetalSite argues this explicitly); several group papers headline accuracy/specificity figures ≥0.98 that are near-trivially achievable at a 1–4% positive rate.

### Gaps
- No public, citable table confirming the "ABC 2394 vs SMR 18" counts in the thesis brief; the DeepEfflux paper's own counts differ (ABC 1,670 / SMR 15). The GenEfflux paper abstract does not list dataset sizes, and I found no data-availability URL for it.
- No explicit license statements for most group datasets. Only RTK_RAG carries a licence file (Academic Free License v3.0, per its README); DeepNeoAG, msCNN-PLM-FAD, RAG_DNA_RNA and DeepEpiIL13 have no LICENSE file in their trees (GitHub API returns no `license` field for them), i.e. technically all-rights-reserved.
- Could not retrieve the ATP-388/ATP-41 residue-level positive/negative counts or their CD-HIT threshold from a primary source within the call budget (only "identity strictly < 40%" for ATP-227).
- RAG_MCNNIL6 and ATP_mCNN abstracts give no per-dataset MCC; the full texts were paywalled.

## Q2. Are the group's GitHub repos complete (data + code + pretrained features)?

### Takeaway
All five repos ship raw FASTA + labels and the feature-extraction scripts, so they are reproducible *in principle*; none ships the extracted embeddings, and three of the five are missing the training/evaluation code, a trained model, an environment spec, or the dataset split actually used in the paper. The most complete are DeepNeoAG and RTK_RAG; msCNN-PLM-FAD is the least usable (its published data is a 20-sequence toy sample, not the 12,850-sample dataset).

### Inferences
- Nobody in this group publishes extracted embeddings. That is actually convenient for a thesis: every reproduction starts from FASTA, so the embedding extraction cost (Q3) is unavoidable and is the dominant compute item, but it also means no hidden feature leakage can be inherited — any leakage must be found in the splits themselves.
- A leakage audit is cheap and well-targeted here precisely *because* the FASTA files are published while the splits' provenance is not documented. RTK_RAG is the strongest candidate: ATP-549 train, 244-protein RAG DB, and 69-protein RTK test are all in the repo, and the README states CD-HIT was applied at 40% (a weak threshold by the field's 30% convention) and, per the paper text, as "a single run … on both data sets" — which does not by itself establish that the RAG database was filtered against the test set.
- Reproducing msCNN-PLM-FAD as a baseline is not currently possible from the repo; a thesis that needs a FAD baseline would have to rebuild the dataset from the paper's description (BioLiP-style FAD sites, BLAST ≤30% identity, 12,850 windowed samples) and should say so explicitly as a deviation.
- The absence of licences means the student should ask the advisors for permission in writing before redistributing any of these datasets in a public thesis repo — and should not mirror them into a public repo by default.

### Gaps
- I did not verify whether RTK_RAG's Colab notebook actually downloads trained weights (fetching the Colab contents was outside the call budget).
- I could not check the `dna_dataset.rar` / `TR735.zip` interiors for an RNA split or for an identity-filter record.
- No repo states a random seed or a fold assignment file, so exact-number reproduction of any of these papers is unlikely; I found no supplementary file claiming otherwise.

## Q3. Compute: embedding extraction time, GPU memory, storage, and Colab/Kaggle quotas

### Takeaway
Per-residue embedding extraction for ~1,000 proteins of ~300 aa is a minutes-to-low-tens-of-minutes job for every model in the list except ESM-2 3B, and fits in 16 GB on T4/P100 at fp16 if sequences are batched by length and long sequences are chunked; the binding constraint is not GPU time but **disk/RAM for the embeddings** (~0.6–1.5 GB per 1,000 proteins per model, and tens of GB once you cache several models × several datasets) and Kaggle's ~30 GPU-h/week quota.

### Cited Findings

**Published runtime anchors (the only primary, citable speed numbers I found)**
- ProtT5/ProstT5 encoder: "Generating embeddings for the human proteome from the Pro(s)tT5 encoder requires around 35m (minutes) or 0.1s (seconds) per protein using batch-processing and half-precision (fp16) on a single RTX A6000 GPU with 48 GB vRAM" — [Rostlab/ProstT5 model card](https://huggingface.co/Rostlab/ProstT5). At 0.1 s/protein that is **~100 s for 1,000 proteins on an A6000**.
- ProtT5-XL half-precision encoder: "This model only contains the encoder portion of the original ProtT5-XL-UniRef50 model using half precision (float16)" and "This model is fully usable on 8 GB of video RAM"; embedding dimension 1024 — [Rostlab/prot_t5_xl_half_uniref50-enc](https://huggingface.co/Rostlab/prot_t5_xl_half_uniref50-enc).
- ProtTrans repo: "experiments were ran in half-precision mode (model.half()), to speed-up embedding generation"; "only GPUs support half-precision currently; if you want to run on CPU use full-precision (not recommended, much slower)" — [ProtTrans GitHub](https://github.com/agemagician/ProtTrans).

**Model sizes / embedding dimensions**
- ESM-2 650M → 1280-dim per-residue (the group's own code uses `esm2_t33_650M_UR50D --repr_layers 33 --include per_tok`, and msCNN-PLM-FAD sets `NUM_FEATURE = 1280`) — [DeepNeoAG README](https://github.com/B1607/DeepNeoAG), [msCNN-PLM-FAD train.ipynb](https://github.com/kioenguyen0207/msCNN-PLM-FAD/blob/main/train.ipynb).
- ProtBert: 400 million parameters, 1024-dim embeddings — [CLAPE preprint PDF](https://arxiv.org/pdf/2306.15912).
- ESM C 600M: "36 layers, width 1152, and 18 attention heads"; open weights on HuggingFace under a **custom non-commercial licence** (non-commercial use by users at non-commercial organizations); "The 600M parameter ESM C rivals the 3B parameter ESM2" — [EvolutionaryScale ESM Cambrian blog](https://www.evolutionaryscale.ai/blog/esm-cambrian), [esmc-600m-2024-12 model card](https://huggingface.co/EvolutionaryScale/esmc-600m-2024-12).
- SaProt: 650M parameters, trained on ~40M sequences+structures, uses Foldseek-derived structure tokens over 20 3Di states, released under **MIT licence** — [SaProt, OpenReview PDF](https://openreview.net/pdf?id=6MRm3G4NiU) / [biorxiv full text](https://www.biorxiv.org/content/10.1101/2023.10.01.560349v1.full).

**GPU hardware the student will actually get**
- FP16 tensor throughput and memory: A100 312 TFLOPS / 2,039 GB/s / 40–80 GB; L4 121 TFLOPS / 300 GB/s / 24 GB GDDR6; T4 65 TFLOPS / 300 GB/s / 16 GB GDDR6; P100 19 TFLOPS / 732 GB/s / 16 GB HBM2 — [JarvisLabs L4 vs A100](https://jarvislabs.ai/blog/l4-vs-a100), [NVIDIA A100 datasheet](https://www.nvidia.com/content/dam/en-zz/Solutions/Data-Center/a100/pdf/nvidia-a100-datasheet.pdf), [NVIDIA L4 product page](https://www.nvidia.com/en-us/data-center/l4/), [Kaggle T4 vs P100 discussion](https://www.kaggle.com/getting-started/561774).
- Important caveat for Kaggle: the P100 has **no usable fp16 tensor cores** (19 TFLOPS fp16 vs the T4's 65), so fp16 on P100 buys memory but little speed.

**Storage of per-residue embeddings — arithmetic, not a cited measurement (my calculation)**
- 1,000 proteins × 300 residues = 300,000 residue vectors. float16: 1024-dim → 614 MB; 1152-dim (ESM C) → 691 MB; 1280-dim (ESM-2 650M) → 768 MB; 2560-dim (ESM-2 3B) → 1.54 GB. In float32 double all of these.
- The group's own sliding-window pipelines multiply this: RAG_DNA_RNA's `get_dataset.py` with `-w 7` produces a (residues × 15 × dim) tensor — for TR735's 196,736 residues at 1024-dim float16 that is **~6.0 GB for one dataset, one model**. Window expansion, not the raw embeddings, is what blows past Colab's disk.

**LoRA / fine-tuning feasibility — Schmirler et al. 2024 (the directly relevant study)**
- Hardware: trained on "a single NVIDIA A10G GPU with 24GB" — [biorxiv full text of the paper](https://www.biorxiv.org/content/10.1101/2023.12.13.571462v2.full), published as [Nat Commun 15, s41467-024-51844-2 (2024)](https://www.nature.com/articles/s41467-024-51844-2).
- "mixed precision training nearly halved the required GPU memory without performance loss"; with memory-efficient techniques they could "fine-tune most pLMs tested here even with on older GPUs with as little as 8GB memory" — [biorxiv](https://www.biorxiv.org/content/10.1101/2023.12.13.571462v2.full).
- Maximum sequence length before OOM: ~400 tokens on 8 GB, ~1,000 tokens on 18 GB, ~1,500 tokens on 24 GB — [biorxiv](https://www.biorxiv.org/content/10.1101/2023.12.13.571462v2.full).
- "both full model fine-tuning and parameter-efficient LoRA fine-tuning required the same amount of GPU memory and only differed in training speed"; "For the largest model (ESM2 3B), LoRA was about a 4.5-fold faster", while for ESM2-8M LoRA was marginally *slower* than full fine-tuning — [biorxiv](https://www.biorxiv.org/content/10.1101/2023.12.13.571462v2.full).
- Expected payoff for per-residue tasks is small: secondary structure improved "up to 1.2 percentage points", disorder "2.2 percentage points"; mutation-landscape tasks benefited substantially more — [biorxiv](https://www.biorxiv.org/content/10.1101/2023.12.13.571462v2.full).
- They recommend mixed precision as the primary efficiency measure, with "gradient accumulation and DeepSpeed's CPU-offloading … reserved to avoiding memory constraints", and ship "easy-to-use notebooks to fine-tune all models" for per-protein and per-residue tasks — [biorxiv](https://www.biorxiv.org/content/10.1101/2023.12.13.571462v2.full). ProtTrans also hosts LoRA fine-tuning notebooks for ProtT5 on per-residue and per-protein tasks — [ProtTrans GitHub](https://github.com/agemagician/ProtTrans).

### Inferences
*(the following are my estimates, flagged as such — I found no published per-GPU benchmark for these specific models)*

- **Estimated** extraction time for 1,000 proteins × 300 aa, fp16, batched by length, forward pass only. Using the forward-pass FLOP approximation 2·N_params·N_tokens (3·10⁵ tokens) and assuming only ~15–25% of peak fp16 throughput is achieved at these short sequence lengths:
  - ESM-2 650M (3.9×10¹⁴ FLOPs): A100 ≈ 0.5–1 min; L4 ≈ 1–2 min; T4 ≈ 2–4 min; P100 ≈ 7–15 min.
  - ESM C 600M (3.6×10¹⁴, 1152-dim): essentially the same as ESM-2 650M.
  - ProtT5-XL encoder (~1.2B enc. params, 7.2×10¹⁴): A100 ≈ 1–2 min; L4 ≈ 2–4 min; T4 ≈ 4–8 min; P100 ≈ 15–30 min. Sanity check against the only published anchor: 0.1 s/protein on an A6000 → ~100 s for 1,000 proteins, consistent with the A100 estimate.
  - SaProt 650M: ≈ ESM-2 650M for the forward pass, **but** it additionally needs a structure (PDB/AlphaFoldDB) per protein and a Foldseek 3Di tokenisation step, which is CPU work not covered by the above and is the real cost driver for a sequence-only benchmark.
  - ESM-2 3B (1.7×10¹⁵, 2560-dim): A100 ≈ 3–6 min; L4 ≈ 8–15 min; T4 ≈ 15–30 min; P100 ≈ 35–70 min. Weights alone are ~5.6 GB in fp16, so a T4/P100 at 16 GB works only with modest batch sizes and sequence chunking.
- **Estimated** peak GPU memory, fp16, forward-only, batch sized to ~4,000–8,000 tokens: ESM-2 650M ~3–5 GB; ESM C 600M ~3–5 GB; ProtT5-XL half encoder ~4–6 GB (the card's "fully usable on 8 GB" is the hard anchor); SaProt 650M ~3–5 GB; ESM-2 3B ~8–12 GB. All fit on a T4/P100 (16 GB) if long sequences (>1,500 aa) are chunked with overlap; attention is quadratic in length, so a single 3,000-aa protein can OOM a 16 GB card at ESM-2 3B even with batch size 1.
- **Budget arithmetic** under 45 GPU-h/week: a full sweep of 5 PLMs × 4 datasets of ~1,000 proteins is a few GPU-hours of extraction, i.e. ~5% of one week's budget. Even 10× that is affordable. The thesis is therefore *not* compute-constrained on embeddings — it is constrained by storage and by the number of training runs. Downstream multi-window CNNs on cached embeddings are minutes per run on any of these GPUs, so dozens of seeds/folds are affordable (important: an audit thesis needs many repeats to make its negative results credible).
- **Colab Pro's 100 CU/month is the real scarcity**, not hours: at the measured rates that is ~84 h on T4, ~58 h on L4, or only ~18.5 h on an A100 40 GB per month. Combined with Kaggle's ~30 GPU-h/week free quota, the "45 GPU-h/week" figure in the brief is realistic only if most hours are Kaggle T4×2/P100 and Colab is reserved for the few jobs that need >16 GB or an A100.
- **LoRA verdict: feasible, but the wrong lever for this thesis.** Schmirler et al. show LoRA and full fine-tuning need the *same* memory, so LoRA's benefit on a T4 is speed, not fitting; ESM-2 650M fine-tuning fits in 8–24 GB with mixed precision provided sequences are capped at ~400 tokens (8 GB) / ~1,000 (18 GB) / ~1,500 (24 GB) — which is a genuine problem for whole-protein binding-site datasets where many chains exceed 1,000 aa and would need chunking. And the reported per-residue gains (1.2–2.2 percentage points) are small relative to the variance an undergraduate project will have, so a fine-tuning-centred thesis risks spending the whole budget to produce a statistically indistinguishable result. Fine-tuning as *one* controlled comparison arm is affordable; as the thesis's main contribution it is a poor risk/return trade at 45 GPU-h/week.

### Gaps
- No primary, published benchmark of ESM-2 650M / 3B / ESM C 600M / SaProt extraction throughput on T4, L4, A100 or P100. Every time and memory figure above marked "estimated" is my own FLOP-based calculation, not a measurement; the only measured anchor in the literature is ProtT5/ProstT5 at 0.1 s/protein on an A6000 48 GB. The student should measure this directly in one 10-minute Kaggle session before committing to an experiment plan.

- ESM C's licence is "custom non-commercial" — I did not verify whether a university thesis in Vietnam counts as "a non-commercial organization" under its exact terms; the student should read the licence text before building the thesis on ESM C.
