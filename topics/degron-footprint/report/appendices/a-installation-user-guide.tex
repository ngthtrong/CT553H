\chapter{INSTALLATION AND USER GUIDE}\label{app:installation}

\section{Installation Requirements}
\subsection{Hardware Requirements}
CPU inference runs on one local computer. Record actual OS, CPU, RAM and free disk in the local test
report; batch/import/project storage requirements remain to be measured. A GPU is not required by the
runtime application. Offline research training has separate requirements.
\subsection{Software Requirements}
The baseline uses a Python virtual environment and pinned backend dependencies, Node/npm with the
frontend lockfile, and locally prepared reference data/model weights. The target adds local PostgreSQL
and a job worker. Exact versions are recorded by the implementation's requirements/lockfiles;
PostgreSQL/job integration is still pending. The research runner additionally uses its own packages
and MMseqs2; these are not all required for serving predictions.

\section{Local System Execution}
There is one local web application. Public hosting, VPS, domain and TLS deployment are outside the
required workflow. All application listeners must be bound to loopback.

\subsection{Existing Baseline Commands}
From the repository root, create/install the baseline backend environment with
\nolinkurl{make -C topics/degron-footprint/system/app venv}, then run
\nolinkurl{make -C topics/degron-footprint/system/app dev-api}.
The API listens on \nolinkurl{http://127.0.0.1:8000}. On first run this command prepares a SQLite
development database from the local research checkout; it does not start the planned PostgreSQL
workspace or durable worker. The existing development ETL's default ClinVar subset must be recorded
when interpreting annotations.

In a second terminal enter \nolinkurl{topics/degron-footprint/system/app/frontend}, run
\nolinkurl{npm ci}, then \nolinkurl{npm run dev -- --host 127.0.0.1}. Open
\nolinkurl{http://127.0.0.1:5173}. Use the real backend; mock mode contains synthetic scores.
These commands are read from the baseline guides and were not executed as application acceptance
in this document-update task.

\section{User Guide}
The target sequence is: create/open a project; choose single peptide, peptide batch or whole protein;
review syntax/domain/coverage; submit and inspect per-tile results; view ClinVar/reference evidence;
import CSV/TSV with assay/units/replicates and fix validation errors; explicitly commit; compare compatible
observations; export scores and provenance; reopen history. Unsaved single-tile previews are transient;
saved work persists until deletion. Deletion presents dependencies and requires confirmation.

\section{Offline Research Campaign Workflow}\label{sec:research-local-guide}
The research supervisor is separate from the application's API and job worker. It uses the pinned
full-PSI data bundle, pretrained-weight caches and a CUDA environment. From PowerShell at the
repository root, \nolinkurl{./status-local.cmd} inspects the campaign. To execute or resume permitted
work, \nolinkurl{./run-local.cmd --hours 2} starts a visible session. Request a safe pause using
\nolinkurl{./pause-local.cmd} or Ctrl+C in that session. Training commits recovery checkpoints
approximately every 120 seconds; an abrupt window close can lose work since the last commit.
These are operational commands, not commands executed during this thesis-update review.

The graph first checks the runtime/data identity and imported reference outputs, then verifies
tokenizer alignment and extracts frozen features for each cached checkpoint. It runs the family ridge
grid and matched frozen/LoRA tuning, collects OOF predictions, fits CV calibrators, evaluates the
locked W5-D transfer recipe and writes the final report. Complete jobs are skipped when resuming
the same compatible campaign; previous source output must remain available for inherited artifacts.
Changing code, data, protocol or relevant runtime properties can create a new identity and must not
be bypassed by editing a manifest or copying arbitrary checkpoints.

On 6 November the runnable graph has 633 completed jobs and two pending input-dependent
extensions. A session that reports zero executed jobs and then ends has no eligible compute left;
restarting it alone does not provide the missing reviewed external or structure inputs. No further
training is needed to reproduce the present analysis from the saved artifacts. Cached model/data
work can be read offline; acquiring new sources or absent model/dependency files is a preparation
step that may require connectivity.

For evidence regeneration, enter the research campaign directory and run
\nolinkurl{python analyze-local-output.py}. This reads saved OOF artifacts, verifies provenance and
recomputes analysis without loading trained checkpoint objects. From the repository root,
\nolinkurl{python topics/degron-footprint/research/output-review-2026-11-06/audit.py}
rechecks selected source hashes and exports the full evidence inventory. The report-asset generator
then rebuilds tables and scientific figures from the exported JSON. Regeneration is an analysis task;
it does not promote a candidate into the application.
